# 通用求解工具：接手缺口分析

> 目标从「可信的物理直觉 + 量级工具」升级为「凝聚态 → 液体/分子自旋 → 量子计算 → 量子电路的通用求解工具」。
> 本文件是接手路线图：先说清"通用求解工具"到底意味着什么，再逐条对照现状，给出结构性缺口与分阶段接手计划。
> 数字与文件名都来自当前实现，可复现。

## 0. 先给"通用"一个可验收的定义

一个程序要被称为"通用求解工具"，最少要同时满足五条（缺一条都只是"一摞演示"）：

1. **任意输入**：晶格 / 基元 / 哈密顿 / 自旋模型 / 门列表 / 器件几何都能由用户定义，而不是写死 Si/Ge/C、方格子、Bell 电路。
2. **统一求解流程**：`定义问题 → 离散化 → 求解 → 观测`，四步对每个域是同一套信封，换内核不换壳。
3. **可编程**：能被脚本/其他程序调用（`atlas.solve(problem) → solution`），不是只能点 GUI 或单点 MCP。
4. **数值可信**：收敛判据、误差带、单位、出处、可复现（seed/版本/参数快照）全程携带。
5. **规模可控**：计算不卡 UI；超胞 / 多比特 / 大体系有对应的后端路径。

第 4 条（P0/P2 那批）我们已经做得不错；**卡住"通用"的是 1、2、3、5 四条，而它们的共同根源是同一个架构问题。**

## 1. 结构诊断（比"缺物理"更根本）

读代码能得到一个确定的结论：

- **全局状态 `S` 是一袋扁平参数**（`src/main.js` 里 ~45 个键），十层参数混在一起，还有 `Temp`/`temp`、`nq`/`nq2` 这种历史重名。这是"每层各写各的"的直接后果。
- **问题定义没有 IR**：材料 = `materials.js` 里 5 个硬编码对象；自旋模型 = `magnon.js` 里写死的方格子；电路 = `GATE_LIST` 固定的十来个门。没有任何一处允许"定义一个新的晶格/哈密顿/门"。
- **自定义材料只通到器件层**（`device.js` 的 `saveCustomMaterial`），能带/光谱根本用不了。
- **求解器没有注册表**：16 个 `phys/*.js` 各自为政，没有统一的 `solve(spec)` 接口，观测（`readout`）和数据（`E(k)`/`ε(ω)`/`ρ`）的形状每层不一样。
- **没有编程 API**：MCP 是单点调用、导出是 CSV，中间没有 `atlas.solve()` 这一层库接口。
- **计算在主线程同步跑**：EPM 对角化、JDOS、Monte Carlo 全在渲染进程里，规模一上去就冻结 UI。

一句话：**现在不是"缺某个模块"，而是"每个域都是一个孤立的特化小程序"，它们共享的只有 UI 和一层扁平状态。**

## 2. 结构性缺口（G0–G5，这是接手的第一刀）

| 编号 | 缺口 | 现状证据 | 影响 |
|---|---|---|---|
| **G0** | 无统一问题描述 IR | `S` 扁平袋 + 硬编码材料/模型 | 「通用」无从谈起，所有上层都卡在这 |
| **G1** | 无统一求解流程信封 | 16 模块各自 `build(S)`/`readout(S)`，接口不齐 | 无法注册、无法组合、无法批量 |
| **G2** | 输入不可定义/不可导入 | 晶格、形状因子、门列表都写死 | 换一个材料/模型就得改代码 |
| **G3** | 无编程 API | 只有 MCP 单点 + CSV | 无法嵌入外部工作流、无法做参数扫描 |
| **G4** | 数值后端单一、阻塞 UI | 全在主线程同步 JS | 上规模即冻结；多比特态矢 n>14 爆内存 |
| **G5** | 无版本化 spec / 可复现层 | 有 seed/元数据，但没有 spec 的版本与 I/O 对拍 | 结果无法"同样输入重跑"或与外部工具对拍 |

## 3. 物理缺口（沿用缺口分析，按"通用"重新排序）

> 完整清单见 `缺口分析.md`（P0–P3）。这里只列"挡在通用求解路上"的：

| 域 | 挡住"通用"的缺口 | 现状 |
|---|---|---|
| 能带/光谱 | 形状因子写死、无 SOC、无自洽、无任意晶格 | 5 材料、标量赝势、46 PW 标定 |
| 自旋 | 晶格写死方格子、仅共线、仅 2 子晶格 | magnon.js 已对角化但模型封闭 |
| 液体/分子自旋 | 只有 RSA 硬球，无真实势、无 MD、无分子自旋多体 | `dynamicFactor` 是唯象扩散 |
| 量子态/电路 | 门集固定、噪声只有振幅/相位阻尼、无读出误差、n>4 无近似 | 精确态矢 + 密度矩阵 |
| 器件 | 1D，无 2D/3D 几何、无像素间电荷共享 | Hecht/泊松/MC 降维 |

## 4. 接手路线（分阶段，每阶段有可验收产出）

### Phase 1 — 统一信封 + 求解器注册表（先做，最值钱）

不碰任何数值内核，只收口接口。定义：

```
Problem   = { kind, spec, params, observables }
Solution  = { problemId, solver, version, data, meta, units, provenance, convergence, error }
```

- `kind ∈ {crystal, bands, spectra, spin, liquid, quantum, circuit, device}`；
- `spec` 是**域相关的模型定义**（见下），`params` 是数值参数，`observables` 声明要什么；
- `solverRegistry[kind].solve(problem) → solution`，每个域一个内核。

**样板先做两个域**：`bands`（最新、有收敛契约）和 `spin`（magnon.js 已经朝 spec 化走了 J₂）。这两个迁移成功 = 信封定型，其余 8 个照抄。

验收：`atlas.solve({kind:"bands", spec:{...}, params:{nG:46,mesh:6}})` 能跑出和现在 GUI 一致的 `E(k)`，且带 `convergence` 字段。

### Phase 2 — 通用输入（G2）

把写死的东西抽成可定义、可导入（JSON）的 spec：

- 晶格 `{a1,a2,a3}` + 基元 `basis` + `nElec` + `formFactors`（vtab 从 materials.js 拆出来当输入）→ 能带/光谱就能换任意晶体；
- 自旋模型 `{lattice, J:{nn,nnn}, D, B, S}` → magnon 换任意晶格；
- 门列表 + 噪声模型 `{gates:[{name,targets,params}], noise:{T1,T2,measErr}}` → 电路接受任意门与误差；
- 液体 `{nAtoms, density, sigma, potential}` → 从 RSA 硬球扩到可换势。

验收：新增一个材料/晶格/门**不改代码**，靠一个 JSON spec 跑通并出图。

### Phase 3 — 编程 API + 批量（G3）

- `atlas.solve()` 作为库导出（ESM 包 + 可选 WASM 核心）；
- 参数网格扫描 → 一张结果表（复用 MCP 的多点能力，但要一次会话批量）；
- 长任务进 **Web Worker / WASM**，不卡 UI（G4 的一半）。

验收：一段脚本批量扫 10 个 J₂ 值，得到 ε₂/色散随参数变化的 CSV + 图。

### Phase 4 — 物理内核补强（逐域到 reference 级）

按"通用求解"最缺的域排序，每个都按本项目一贯的"先对拍、再标定、写契约"：

1. **自旋**：非共线、任意晶格、多子晶格（ED/DMRG/MC 做有限温度与基态）——距"分子自旋"最近；
2. **量子电路**：通用噪声通道（Kraus 任意）、读出误差、n>4 用 Clifford/张量网络近似；
3. **液态**：真实对势（LJ/软球）+ 分子动力学 → g(r)/S(k) 从"形状对"到"定量对"；
4. **能带**：非局域赝势（才有真 SOC）、自洽、更多晶格对称点群；
5. **器件**：2D 几何 + 权重势 + 读出噪声。

### Phase 5 — 可复现 + 外部对拍（G5）

- spec 版本化（含 solver 版本 + 参数快照 + git hash）；
- 与 VASP/SpinW/qiskit/Geant4 的 I/O 对拍文件（POSCAR、SpinW 定义、OpenQASM、几何体）。

## 5. 一个必须说清的范围判断

「凝聚态 + 液体分子自旋 + 量子计算 + 量子电路」四域，在**研究级通用**上等价于再造 VASP/Quantum ESPRESSO + SpinW/McPhase + LAMMPS + QuTiP/qiskit + Geant4——这不是一个单人项目能一次做完的。

本程序能成为的、且值得做成的是：

> **一个统一的「问题 → 求解 → 观测 → 误差」求解框架**，四域各有一个 reference 级内核 + 通用 I/O + 严格的可信度表达；物理深度逐域收敛，而不是一次铺满。

Phase 1–3 做完，它就已经是"通用求解工具"的骨架了；Phase 4 是往里填每个域的物理深度，可以按需排期，每填一个域就多一类可算的问题。

## 5.5 Phase 1 已完成：八域全部迁入信封

`Problem → Solution` 信封 + `solverRegistry` 落地，**八个域全部迁入**（不再是两个样板）。`pnpm test` 第 2 层 `test:solver` 覆盖：

| 域 | 内核 | spec 要点 |
|---|---|---|
| crystal | `crystal.geometry` | `{material}` → 晶格/基元/BZ 面·顶点 |
| bands | `bands.epm` | `{material}` + `{nG,mesh,nBands}` → VBM 对齐 E(k) |
| spectra | `spectra.jdos` | `{material}` + `{nG,mesh,γ,T}` → ε₁/ε₂/α |
| spin | `spin.magnon` | `{kind,S,J1,J2,D}` → 动力学矩阵色散 |
| liquid | `liquid.rsa` | `{N,seed,σ,ρ}` → g(r)/S(k) |
| quantum | `quantum.statevec` | `{n,state}` → 概率/Q-sphere/concurrence |
| circuit | `circuit.statevec` | `{n,ops,steps,noise?}` → 时序/F/纯度/concurrence |
| device | `device.hecht` | `{material,d,V,E,T}` → 标量 + 温/通量扫描 |

关键验收：

- 八个域**每个**都有一条"与直接调 phys 内核逐点一致"的断言（bands 的 gap、spin 的色散、spectra 的 ε₂(0)、liquid 的 g(0)、quantum 的 concurrence、circuit 的末态概率）；
- 信封校验拦截非法问题；求解器内部错误走 `Solution.error` 返回不抛（批量流程能捕获）；`provenance` 区分 calc/calib/input；`convergence` 附收敛/局限说明；
- `test-convergence` / `test-physics` 依旧全绿——迁移是"包壳"，不丢精度。

**迁移中抓到的两个真问题**（都只有"包壳 + 断言"才暴露）：

1. 旧 `materialOf()` 对未知 id **静默回退 Si**（`MATERIALS[id] || MATERIALS.Si`）——通用求解器的"静默错答案"；求解器层改为直接查 `MATERIALS` 并显式抛错。
2. device 的电荷收集效率字段实际叫 `cceAvg` 而非 `CCE`——迁移测试一开始断言错了键名，暴露了"命名散落在各层"的问题（见 G0 的后续清理项）。

**下一步（Phase 2 起步）**：把写死的 `formFactors` / 晶格 / 门列表 / 器件材料表抽成 spec 的可导入 JSON。
`bands` / `spin` / `quantum` / `circuit` 的 spec 已经为此留好了口子（都能接一个完整定义对象，不再只能传 id）。


## 5.6 Phase 2 第一步：自定义材料已打通（bands/crystal/spectra）

`src/solver/material.js` 提供 `defineMaterial(spec)`：把一个不完整的用户 spec 规范化成
EPM 能直接吃的完整材料对象，并对缺失字段显式报错。`bands` / `crystal` / `spectra` 三个域的
`resolveMaterial` 现在统一走它——字符串进内置表，对象进"定义/规范化"。

| 能力 | 验收（`test-solver` 已断言） |
|---|---|
| 自定义晶格常数 | 金刚石 a=5.8 Å → gap 1.9276 eV（Si 1.1347），改 a 改带隙 |
| 自动推导 A | 由 `kind + a` 推导正格子矢量（diamond/fcc/rocksalt/bcc 四种） |
| 缺字段显式报错 | 缺 nElec/vtab → "材料定义无效：…"，不静默回退 |
| bcc / rocksalt | 自定义 bcc 材料能带 + crystal BZ 都跑通 |

**又一个诚实发现**：同一套 Si 形状因子，把 a 压到 5.0 Å 时 gap 变成 0（模型预测"带隙闭合"）——
这直接证明了"形状因子只在其拟合的 a 处有效"。测试里把这条钉成了显式断言，而不是当成 bug 修掉：
它和 §4.13 的 SOC 负结果一样，是"这个模型能信到什么程度"的边界标记。

**Phase 2 还剩**：把 `formFactors` 本身从"查内置表"进一步放开（现在自定义材料还得自带 vtab），
以及把自旋模型的晶格、门列表、器件材料表按同样方式抽成 spec 可导入。`bands` 的自定义材料已打通，
是这一阶段的第一块里程碑。


## 5.7 Phase 2 第二步：自旋模型的晶格也解开了

`src/phys/magnon-generic.js` 新增**任意晶格**的共线铁磁线性自旋波：

- `bonds: [{r:[x,y], J}]` —— 键矢量以最近邻距离为单位，用户给什么晶格就是什么晶格；
- `path: [{label, q}]` —— 任意高对称路径；
- `J(q) = Σ_b J_b·cos(q·r_b)`，`ω(q) = 2S(J(0)−J(q)) + 2DS`。

`spin` 求解器的 spec 现在有两种形态：方格子专路（`{kind,J1,J2,D}`，向后兼容）与任意晶格通路
（`{bonds, path, S, D}`）。验收（`test-solver` §8）：

| 断言 | 结果 |
|---|---|
| 键表方格子 = legacy 方格子 | 逐点差 **3.6e-15** |
| 一维链 ω(X) = 8SJ | 8.0000（解析精确值 8） |
| spin 求解器任意晶格通路 | meta.lattice=custom |
| 缺 path | 显式报错 |

**范围边界（诚实版）**：任意晶格只覆盖**共线铁磁**（单子晶格，B=0）。AF 双子晶格需要二分划分，
泛化代价高，仍走方格子专路。这一步的里程碑意义在于——"换晶格不改代码"在自旋域已经成立；
`bonds` 就是那个通用输入的口子，后面加非共线/多子晶格都是在它上面扩展。

**Phase 2 还剩**：门列表（circuit）与器件材料表（device）按同样方式抽成 spec 可导入，
以及能带域把 `formFactors` 本身从"自带 vtab"进一步放开（支持查表名）。


## 5.8 Phase 2 第三步：门列表也抽成 spec

`circuit` 求解器的 ops 现在接受三种门（`src/solver/circuit.js`）：

- 命名门 `{gate:"H"|"X"|"Y"|"Z"|"S"|"T", qubit, step}`
- 参数化旋转 `{gate:"Rx"|"Ry"|"Rz", theta, qubit, step}`
- **任意 2×2 复矩阵** `{gate: [[[re,im],[re,im]],[[re,im],[re,im]]], qubit, step}`
- 双比特门 `{gate:"CNOT"|"CZ"|"SWAP", control, qubit, step}`

验收（`test-solver` §9）：

| 断言 | 结果 |
|---|---|
| Rx(π)|0⟩ → |1⟩ 概率 | 1.000000（=X，至全局相位） |
| 任意矩阵 = 命名 H | |0⟩ 概率 0.5，逐点一致 |
| 未知门名 | 显式报错 "未知门" |
| Ry(π) ≈ Y | |1⟩ 概率 1.0 |

**范围边界**：任意 2×2 矩阵 + 噪声的组合还没打通（`simulateNoisy` 只认命名门 + CNOT/CZ），
留待 Phase 4（量子噪声补强）时一起做——那时噪声通道本身也会抽成任意 Kraus。

**Phase 2 进度**：自定义材料（bands/crystal/spectra）✅、任意晶格（spin）✅、门列表（circuit）✅。
还剩：device 材料表抽 spec、bands 的 formFactors 支持查表名。


## 5.9 Phase 2 完成：四处硬编码输入全部抽成 spec

`device` 材料表（`src/solver/detector.js` + `deviceModel`/`monteCarlo` 支持对象）与
`bands` 的 formFactors 查表名（`formFactors:"Si"`）落地。**Phase 2（通用输入）收口**：

| 输入 | 之前 | 现在 |
|---|---|---|
| 材料/晶格 | 5 个硬编码 | `defineMaterial({id,kind,a,basis,nElec,vtab 或 formFactors})` |
| 自旋晶格 | 写死方格子 | `{bonds:[{r,J}], path:[…]}` 任意共线 FM 晶格 |
| 门列表 | 写死十几个门 | 命名门 + Rx/Ry/Rz(θ) + **任意 2×2 复矩阵** + CNOT/CZ/SWAP |
| 器件材料 | 9 个硬编码 | `defineDetector({Eg,mu_e,mu_h,tau_e,tau_h,W,rho_m,comp,…})` |

**迁移中又抓到一个真 bug**：`deviceModel` 读的是 `opts.thickness/voltage/energy/temp`，而求解器之前传的是
`d/V/E/T`——导致用户改厚度/偏压**根本没生效**（一直用默认 1 mm / 300 V）。靠"更厚(d=3) → CCE 更低"
这条断言才暴露（0.606 vs 0.885）。现在映射修正，参数真正流进模型。

**Phase 2 里程碑达成**："换材料 / 换晶格 / 换门 / 换探测器材料——都不改代码"。这是「通用求解工具」定义里
五条中的第 1 条（任意输入）在四个域全部成立。

**下一步（Phase 3 — 编程 API + 批量）**：
1. `src/solver/index.js` 作为库出口（`solve`/`makeProblem`/`defineMaterial`/`defineDetector`/registry），
   供外部脚本 `import { solve } from 'quantum-atlas/solver'`；
2. 参数网格批量：`sweep(problem, {key, values})` → 结果表 + 收敛带；
3. 长任务进 Web Worker / WASM（不卡 UI）。


## 5.10 Phase 3（编程 API + 批量）前两步落地

- `src/solver/index.js` —— 库出口：`import { solve, sweep, defineMaterial, defineDetector, rotationMatrix }`；
- `src/solver/sweep.js` —— 参数网格批量：`sweep(problem, {path, values, extract?})` → `{table}`。

验收（`test-solver` §11）：

| 断言 | 结果 |
|---|---|
| index.js 库出口完整 | solve/sweep/defineMaterial 都在 |
| spin sweep spec.J1 ∈ {0.5,1,2} | 带宽 8.00 < 16.00 < 32.00（单调） |
| device sweep spec.d ∈ {1,2,3} | CCE 0.885 > 0.709 > 0.606（单调） |
| bands sweep params.nG ∈ {46,65} | 两个截断带隙都有限 |
| sweep 缺 path | 报错 |

**Phase 3 还剩一块**：长任务进 Web Worker / WASM（现在 solver 是纯同步 JS，批量在 GUI 里跑会卡 UI；
但作为库被 Node/脚本调用时不存在这个问题）。这一块是纯前端工程，不涉及物理内核，可作为 Phase 3 尾部单独排期。

至此「通用求解工具」五条定义里：
1. 任意输入 ✅（Phase 2，四域）
2. 统一求解流程 ✅（Phase 1，信封 + registry）
3. 可编程 ✅（Phase 3 前两步：库 + sweep；批量出图仍待 Worker 那步）
4. 数值可信 ✅（P0/P2：收敛、误差带、provenance）

## 5.12 Phase 4 第一步：有限温度磁振子

`src/phys/magnon-thermal.js` 落地两个教科书级量，`spin` 求解器接上温度：

- `bose(ω, T) = 1/(e^{ħω/kT}−1)` —— 量子统计（ω 单位 meV、T 单位 K，kT=0.08617·T meV）；
- `occupations(ω[], T)` —— 沿色散曲线的 Bose 占据 + 平均占据（跳过 ω=0 的 Goldstone 零点模式，避免发散）；
- `magnetizationT(T, {S, Tc})` —— 平均场磁化（复用 `spin.js` 的 self-consistent Brillouin）。

`spin` spec 增加 `T`（温度）与 `Tc`（居里温度），data 增加 `occupation` 与 `magnetization`。

验收（`test-solver` §12，5 条）：

| 断言 | 结果 |
|---|---|
| bose(1 meV, 300 K) | 25.3551（与精确式逐位一致） |
| 经典极限 n(ω→0) → kT/ħω − 1/2 | 25851.4（误差 <1%） |
| 磁化 m(0)=1 > m(150) > m(Tc) | 1 / 0.937 / 0.149 单调 |
| 零温 occupation=null、m=1 | ✅ |
| 有限温 occupation 有限且 >0 | 平均占据 38.21 |

**抓到一个发散**：D=0 时 Γ 点 ω=0，`bose(0)` 本会返回 ∞——这是 Goldstone 零点模式（物理上对 BZ 积分测度为零，
按点取平均却是发散）。修法是 `occupations` 跳过 ω≤1e-9，`bose(ω≤0)` 返回 0。

**边界（诚实版）**：这是"零温色散 + 量子统计占据 + 平均场磁化"，**不是**自洽的有限温自旋波理论
（色散本身不随 T 重整化）。但已把"有限温度"从"唯象展宽"升到"量子统计"。

**Phase 4 还剩**：自旋非共线/多子晶格、电路任意 Kraus 噪声通道、液态真实势+MD、非局域赝势 SOC。


## 5.13 Phase 4 第二步：任意 Kraus 噪声通道 + 任意门×噪声

- **自定义通道**：任意 2×2 Kraus 算符列表 `{q, kraus:[K0,K1,…]}`；
- **门**：任意 2×2 复矩阵（与无噪声路径对齐），不再只认命名门。

`noise` spec 两种形态：旧 `{T1,T2,gateTime}`（自动转 ampdamp+phasedamp）或新 `{channels:[…]}`。

|---|---|

**Phase 4 进度**：有限温度磁振子 ✅、任意 Kraus 噪声 ✅。还剩：自旋非共线/多子晶格、液态真实势+MD、非局域赝势 SOC。

**边界（诚实版）**：噪声通道是**无关联**的（每比特独立、每步 Markov 化），没有读出误差、

## 5.14 Phase 4 第三步：液态从 RSA 静态跨到 Monte Carlo

`src/phys/liquid-mc.js` 落地 Lennard-Jones + Metropolis Monte Carlo，`liquid` 求解器新增 `method:"mc"`：

- 势：LJ 12-6，截断 rc=2.5σ 并平移（U(rc)=0），约化单位（σ=1、ε=1、T=kT/ε）；
- 采样：局部移动 + 周期边界 + 最小镜像，Metropolis 判据；
- 构型形状与 `liquidConfig` 同构，直接喂 `pairCorrelation`/`structureFactor`。

验收（`test-solver` §14，8 条）：

| 断言 | 结果 |
|---|---|
| Metropolis 平衡使能量下降 | −306.9 ≤ 初始 +31.5 |
| 接受率合理 | 69% |
| g(0)≈0（硬核排斥） | 0.000 |
| 第一峰 >1.5 | 3.08 |
| 远场 g→1 | 0.97 |
| 升温降低第一峰 | 2.28 < 3.08 |
| liquid 求解器 mc 通路 | E=−226、acc=68% |
| rsa 旧通路仍可用 | ✅ |

**抓到一个测试自己的坑**：`rMax=6` 对 N=100/ρ=0.5 的盒子（L=5.85）超过了 L/2=2.9——
周期边界下最小镜像距离上限是 L/2，超过它 g(r) 恒为 0。改成 `rMax=2.8` 后物理量全部正常。

**Phase 4 进度**：有限温度磁振子 ✅、任意 Kraus 噪声 ✅、液态 MC ✅。还剩：自旋非共线/多子晶格、非局域赝势 SOC。

**边界（诚实版）**：这是**平衡态**重要性采样（Metropolis），不是**动力学**（没有真实时间演化/速度自关联），
g(r) 是热力学平衡量所以 MC 够用；但要想自扩散系数/时间关联函数，需要换 MD（Verlet 积分），那是另一个内核。


## 5.15 Phase 4 第四步：多子晶格自旋波

`src/phys/magnon-generic.js` 新增 `frequenciesMulti`/`branchesMulti`，`spin` 求解器新增 `sublattices` 通路：

- 输入：`sublattices=[{S,D},…]` + `bonds=[{a,b,r,J}]` + `path`；
- 共线 FM（B=0）线性自旋波矩阵：`A_αβ(q) = 2δ_αβ[Σ_γ S_γ J_αγ(0) + S_α D_α] − 2√(S_α S_β)·J_αβ(q)`；
- **频率 = A 的本征值**（FM 无反常项，不是 ω²）。

验收（`test-solver` §15，8 条）：

| 断言 | 结果 |
|---|---|
| m=1 退化 = frequenciesGeneric | 逐点一致（4 个 q 点全 0 差） |
| 2 子晶格 Γ 处两支 | {0, 16}（解析 2S[zJ±J(q)] = 2[4±4]） |
| 2 子晶格 X 处两支 | {8, 8}（2[4±0]） |
| spin 求解器多子晶格通路 | 2 子晶格、2 支、最高支 Γ 处 16 |

**踩到两个坑，都靠"退化一致 + 解析对拍"才抓出来**：

1. `Array.prototype.flat()` **不展平 TypedArray**（只对真数组生效）——`[Float64Array(2), Float64Array(2)].flat()`
   仍是一层，导致 `Float64Array.from(...)` 把两个 TypedArray 强制成 NaN。改手动铺平。
2. 把"频率"当成了"频率平方"：FM 无反常项，ω = eig(A) 而不是 √eig(A)。开方后 m=1 都退化不对，
   靠"m=1 必须等于 frequenciesGeneric"这条退化断言当场暴露。

**Phase 4 进度**：有限温度 ✅、任意 Kraus 噪声 ✅、液态 MC ✅、多子晶格 ✅。只剩**非局域赝势 SOC**——
而那一项在 §4.13 已经实证过：局部弱赝势算出的 Δ_SO 只有 0.26 µeV（文献 44 meV），要做必须换非局域自旋相关赝势 +
整套形状因子重标定，是一个独立的大工程，建议单独立项而不是塞进 Phase 4。
